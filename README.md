### CS 230 - Software Design Document Reflection

**Client Summary**  
The Gaming Room needed a cross-platform game called Draw It or Lose It. They required a design for a multi-user, networked application that supports teams, game sessions, and image-based puzzles.

**What I Did Well**  
I communicated the system architecture clearly and organized the design document in a way that made the technical decisions easy to understand.

**Helpful Parts of the Design Process**  
Working through the design document helped me think through the structure of the application before writing any code.

**What I Would Revise**  
I would refine some early sections to be even more concise.

**Interpreting User Needs**  
I focused on scalability, cross-platform support, and multi-user gameplay. Understanding user needs ensured the design supported real gameplay scenarios.

**Approach to Designing Software**  
I broke the system into smaller functional areas and evaluated each one individually. I would continue using structured analysis and modular design techniques in future projects.
